# Bundled suites in agent mode

Two of the bundled suites run only in host mode (`midojo-run --interception host`): [weather](../suites/weather/) and [minibank](../suites/minibank/). Each exports `HOST_TOOLS`, its interception layer runs on each evaluation's host-side interceptor, and its agent gets only that interceptor's URL and token, never the evaluation's session (see [Keep the evaluation out of the agent's reach](../README.md#keep-the-evaluation-out-of-the-agents-reach)).

This is the list of the bundled suites that still run in agent mode, and what each would need to move to host mode.

| Suite | How it runs now | What host mode would need |
| --- | --- | --- |
| [document_assistant](../suites/document_assistant/) | OpenShell, agent mode with `inject_session: false`: the sandbox gets no session, control-plane URL or control token, and nothing in it records calls, so every evaluation's `function_calls` evidence is `incomplete`. The agent is PI with its built-in tools (`read`, `bash`, ...), which run in the sandbox, not over MCP. The injections are seeded files (runtime-file probes); the security checks read what OpenShell observes (files, processes, network) and the utility checks the agent's answer, none the tool calls. | Host mode intercepts MCP tool calls only, and requires `--upstream-mcp-url`. The suite would need its agent's tools served over MCP: a real-tools server for the upstream (as `suites/weather/tools_server.py`), the PI image configured to call them at `MIDOJO_TOOL_URL` with `MIDOJO_TOOL_TOKEN` (as the weather image's `start-agent.sh` does), and a network policy allowing `host.openshell.internal` on the `--interceptor-port`. Its file and shell actions must stay in the sandbox, as its checks observe them there: moving them to the host would leave the OpenShell observations nothing to see. Until then host mode adds nothing its checks read: the session is already out of the sandbox, and no check needs a complete call capture. |
