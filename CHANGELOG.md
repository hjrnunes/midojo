# Changelog

What this fork changes in MiDojo's public API. Read [breaking changes](#breaking-changes) before you upgrade. `midojo`, `midojo-sdk`, `midojo-spec` and `midojo-mim` are released together at the same `0.x` version.

## Unreleased

### Added

- **Injection-spec document v1.** `InjectionSpec.to_document`, `InjectionSpec.from_document`, `InjectionSpec.load_document`, `InjectionSpec.dump_document` and `midojo.injection_spec_document` read and write `schema_version: midojo-injection-spec-v1`, a closed document: every member is written, so two dumps of one injection spec are the same bytes. The reader accepts that version only. The JSON Schema ships in `midojo_spec.schemas/midojo-injection-spec-v1.schema.json` and `midojo_spec.injection_spec_schema.load_schema()` loads it.
- **Verdict document version.** A verdict names its format, `midojo-verdict-v1`. `Verdict.from_document` reads that version only and refuses a document without `schema_version`.
- **Plan codec version.** `midojo_spec.injection.PLAN_CODEC_VERSION` (`midojo-plan-v1`) names the codec `InjectionPlan.to_data` writes, which the v1 injection-spec document's `plan` member holds. The plan carries no version of its own: the document that encloses it names the codec through its `schema_version`, so a change to the bytes the codec writes needs a new document version.
- **Synchronous handle.** `midojo.evaluation_handle.open` returns an `EvaluationHandle` that drives one evaluation from a script with no event loop: `send_turn`, `record_reply`, `seal`, `grade` and `close`. It runs the same `EvaluationContext` on a loop thread of its own, and it states what stays stable (`HANDLE_METHODS`, `HANDLE_API_VERSION`, the exception classes and their `reason` strings). See [the driver guide](docs/guide-driving-midojo.md).
- **Live-evaluation cap.** A process keeps at most `DEFAULT_MAX_LIVE_EVALUATIONS` (8) handles open; `MIDOJO_MAX_LIVE_EVALUATIONS` overrides the cap and `max_live` lowers it for one call. Opening past the cap raises `LiveEvaluationLimitError` before any port is bound.
- **Runtime capability query.** `midojo.runtimes.runtime_capabilities` answers what a runtime can do from its definition alone: no runtime built, no sandbox created, no provider imported.
- **Placement engine protocol.** `midojo_mim.placement.PlacementEngine` decides what a plan places in a tool call's result, apart from the wire: the interceptor forwards and records a call, and the engine answers each placement. `PlanPlacementEngine` is the plan's own engine.
- **`midojo_spec.policy.tool_policy`.** The helper reads a spec's `ToolPolicy` as the interceptor's allowlist and block list, so a caller that builds its own host interception applies the spec's policy the same way the handle does.
- **Judge replay.** A grade keeps the judgements it made, and `grade(spec, snapshot, judgements=first.grade.judgements)` replays them with no judge service. A request without a record is unknown, never False. See [Replay](docs/judge-service.md#replay).
- **`midojo-sdk` as a base dependency.** `midojo` now depends on `midojo-sdk[mcp]` instead of reaching into the SDK's checkout: the driver's adapter for a remote interceptor, `midojo_sdk.binding`, lives in the published SDK (the injection-spec schema, the snapshot encoding, the plan codec and the binding frame codec live in `midojo-spec`, which the SDK depends on), and `[tool.uv.sources]` keeps the workspace link for development. The `suites`, `pyrit` and `dev` extras are unchanged; `jsonschema>=4.23` joins `dev`, since the tests import it directly.
- **Remote interception.** A driver can run the interceptor in a service of its own. `midojo_spec.link` is the codec of the `midojo-binding-v1` frames, the messages' API name, over the WebSocket subprotocol `midojo-binding.v1` (`encode_frame`, `decode_frame`, `encode_message`, `decode_message`, `LinkLost` for a link that ends without an acknowledged `unbind`), and `midojo_mim.link` holds `Link`, `LinkRecorder` and `LinkWorld`, the service's end of the stream. `midojo_sdk.binding.Binding` is the driver's adapter: it dials the service's `GET /v1/bindings` upgrade and offers the subprotocol, sends no heartbeat of its own by default (the driver's frame dispatcher sends `ping` every 5 seconds, `HEARTBEAT_INTERVAL_SECONDS`, while it waits for frames), keeps the service's 15-second expiry and 10-second answer deadline (`HEARTBEAT_EXPIRY_SECONDS`, `ANSWER_DEADLINE_SECONDS`), and redacts the bind credential from websockets' DEBUG log. `midojo-intercept-serve` (`midojo_mim.service`) serves each binding's `/b/<id>/mcp` endpoint and holds the upstream, and `evaluation_handle.open` selects it with `interception=RemoteInterception(url, credential)` or, when no option is given, the `MIDOJO_INTERCEPTOR_URL` and `MIDOJO_INTERCEPTOR_CREDENTIAL` pair; neither keeps the interceptor in the driver's process. The SDK's `mcp` extra declares `websockets>=16,<18`, which the adapter imports directly.
- **`midojo-spec`.** The contracts every reader shares are a package of their own, `midojo-spec` (import `midojo_spec`, `packages/midojo-spec`): the standard library only, no dependency, Python 3.11 and later, so a Garak or consumer environment installs it without MiDojo's runtime. It holds `midojo_spec.injection` (the plan and its codec), `midojo_spec.injection_spec_schema` (the document's schema, as package data), `midojo_spec.snapshot` (the snapshot digest), `midojo_spec.recorder` (the `Recorder` and `WorldState` seams), `midojo_spec.link` (the binding frame codec), `midojo_spec.judge` (the `midojo.judge.v1` request and response rules: `request_id`, `request_problem`, `response_problem`), `midojo_spec.judge_exchange` and `midojo_spec.rubric_judge`, with conformance vectors under `packages/midojo-spec/vectors/` for each contract. A test fails the build if a module imports anything outside the standard library or uses syntax Python 3.11 cannot parse.
- **`midojo-mim`.** The interceptor is a package of its own, `midojo-mim` (import `midojo_mim`, `packages/midojo-mim`): the interceptor service (`midojo_mim.service`, the `midojo-intercept-serve` script), the placement engine (`midojo_mim.placement`), the MCP face (`midojo_mim.mcp.MidojoMCP`) and the recorder and world adapters over a binding's stream (`midojo_mim.link`). It depends on `midojo-spec` and FastMCP (`fastmcp>=3.2.4,<3.3`, which it pins), on the service's web stack and on nothing of the harness, and a test fails the build if a module imports `midojo`, `midojo_sdk` or anything its `pyproject.toml` does not declare. It declares Python 3.11 and later, tests in its own CI job without the harness, and has an image of its own, `packages/midojo-mim/Containerfile`, built from the repository root with `docker build -f packages/midojo-mim/Containerfile -t midojo-intercept-serve .`: the image holds the two packages and no verifier, runtime or control plane, and runs as any user ID. The face takes a `recorder`, a `world` and a `sessions` seam and holds no session token and no control-plane client; the SDK's `midojo_sdk.mcp.MidojoMCP` is that face with agent mode added.
- **The judge exchange record.** `midojo_spec.judge_exchange` fixes `midojo.judge-exchange.v1`, one JSONL row for each model request a judge service makes: the key (`request_id`, `ask`), the judge's identity (`model`, `prompt_version`), the messages sent, the reply or the failed call's label, the status, usage and timing (`started_at` has one shape, `YYYY-MM-DDTHH:MM:SS` with an upper-case `T`, hour 00 to 23, minute and second 00 to 59, an optional fraction of one to six digits, and UTC as `+00:00` or `Z`: a row with any other zone, separator, form or spelling of a zero offset, such as `+0000`, `-00:00`, a lower-case `t`, hour 24 or a week date, is refused on every Python version), and the SHA-256 of the judge request and of the reply, which equal the digests the sealed grade's judgements hold. `ExchangeLog` appends rows thread-safely (every log on one file in a process shares one lock and count, whatever path each names, and a write that fails is cut back; one process appends to a file at a time), every integer in a row fits 64 bits, `read_exchanges` reads them strictly and refuses an unredacted row whose digests are not those of its text, and `Exchange.observed` redacts secrets from the text in one pass while it keeps the digests of the original; it never rewrites `model` or `prompt_version`, which a replay checks, and refuses a secret that occurs in either. `rubric_judge.http_judge` takes an `observer` that receives each request's outcome, so a judge service keeps a row for a failed call too (a failure the module does not name is observed under its class name and raised as it was), and `JudgeCallError` carries the HTTP `status`.

### Changed

- **The episode API is the injection-spec API.** The names are `InjectionSpec`, `EvaluationContext`, `EvaluationHandle`, `EvaluationResult`, `EvaluationStep`, `EvaluationRun`, `InjectionSpecDocumentError` and `open_evaluation`; the modules are `midojo.injection_spec`, `midojo.injection_spec_document`, `midojo.evaluation_context` and `midojo.evaluation_handle`, and the schema module is `midojo_spec.injection_spec_schema`. The deprecated aliases are gone: the modules `midojo.episode`, `midojo.episode_document`, `midojo.episode_context`, `midojo.episode_handle` and `midojo_sdk.episode_schema`; the classes `Episode`, `EpisodeContext`, `EpisodeHandle`, `EpisodeResult`, `EpisodeStep` and `EpisodeRun`; the functions `open_episode` and `ControlPlane.open_episode`; and the constant `EPISODE_DOCUMENT_V1`. Two host-facing keyword arguments keep their pre-rename names as deprecated forwarding aliases for one cycle: `open_evaluation(episode=...)` and `MidojoInjectionSpecTarget(episode_for_payload=...)` warn `DeprecationWarning` and pass the value to `injection_spec=` and `injection_spec_for_payload=`; passing both names, or neither, raises `TypeError`. The readers of recorded data keep the `episode_trace` and `ipi_episode` notes in a snapshot.
- **The other `episode` spellings follow the glossary.** `YAMLTaskSuite.episode` is `YAMLTaskSuite.injection_spec`, `DEFAULT_EPISODE_NAME` is `DEFAULT_EVALUATION_NAME` (whose value is `evaluation`), a run with no `run_id` is named `evaluation-<hex12>`, the handle's loop thread is `midojo-evaluation-handle`, and the PyRIT target is `MidojoInjectionSpecTarget` with an `injection_spec_for_payload` argument. The live cap is `DEFAULT_MAX_LIVE_EVALUATIONS`, its variable is `MIDOJO_MAX_LIVE_EVALUATIONS`, and the error is `LiveEvaluationLimitError` with reason `live-evaluation-limit`; the old variable `MIDOJO_MAX_LIVE_EPISODES` still sets the cap, with a `DeprecationWarning`. The handle's guide moved to [docs/evaluation-handle.md](docs/evaluation-handle.md), and its example is [examples/drive_evaluation.py](examples/drive_evaluation.py).
- **The snapshot encoding is `midojo_spec.snapshot`.** The digest, its canonical encoding and `SNAPSHOT_DIGEST_VERSION` live in `midojo-spec`, so a client verifies a snapshot without importing `midojo` or the SDK. `midojo.control_plane.state.snapshot_digest` remains as a wrapper over it.
- **The served OpenAPI text states the unfinished-call rule.** `_INTERCEPTION_DESCRIPTION` now says that an unfinished call the session can no longer report — revoked or expired — marks `function_calls` evidence incomplete: the sealed record holds a call whose result is unknown.
- **A refused tool call logs one line, not a traceback.** A blocked or denied call still reaches the agent as the same `ToolError`; the driver now gets an INFO line from the SDK and no FastMCP traceback on stderr.
- **`evaluation_handle.open` refuses `run_id` without an open run.** Passing `run_id` with a runtime whose run is not open raises `ValueError` naming `run_id`, before any live slot, port or sandbox. Start the run and pass the runtime it owns, or leave `run_id` out.
- **`open_evaluation` refuses an unenforced tool policy.** The asynchronous API has no interceptor of its own, so it never applied `spec.tools`. It now refuses an injection spec whose policy blocks a tool, unless the `interception` you pass blocks the same tools, rather than opening with the block silently unenforced. The handle's interceptor remains the only place a policy is enforced.
- **Agent mode is parked, and a driver that asks for it is refused by name.** The SDKs (`interception/python-sdk`, `interception/pi-sdk`), the control plane's `/agent` routes and the seams they use (`Recorder` and `WorldState` in `midojo_spec.recorder`, `Sessions` on the face, `midojo_sdk.mcp.MidojoMCP` as the face with a control plane added) stay, with their tests, for a later agent-mode route. The interceptor service never takes the agent's session: it refuses a `bind` whose `faces` is anything but `["mcp"]` (`unsupported`), whose `host_tools` is not empty (`unsupported`, since it runs none) or that carries a session token, a control-plane URL or any other field it does not define (`invalid_bind`), and a session header on an agent's request changes nothing it records. `evaluation_handle.open` raises `TypeError` for an `interception` that is neither a `HostInterception` nor a `RemoteInterception`, and `midojo-run` refuses a suite whose tools live on the host without `--interception host`. A test reads the literal import names in this repository's own Python source (`src`, `suites`, `scripts`, `examples`, the SDK's, `midojo-spec`'s and `midojo-mim`'s source) and in the TypeScript SDK's source, the dependencies in its four `pyproject.toml` files and the TypeScript SDK's `package.json`, and the packages in `uv.lock`, and fails the build if one name starts with `asago`. It does not read a name built at run time, a tests tree, or a shell, YAML, Containerfile or document file.

### Fixed

- **The snapshot codec refuses `NaN` and the infinities in a snapshot's content, wherever they come from.** `verified`, `snapshot_digest` and `SnapshotView.from_json` accepted a snapshot object holding a non-finite `float` once its `snapshot_id` was the digest of that float's bits, and accepted JSON text whose number is past the range of a double (`1e999`, which `json.loads` reads as an infinity without asking `parse_constant`); only the bare constants `NaN` and `Infinity` were refused. `midojo_spec.snapshot.canonical` now raises `DigestFault` for a non-finite float, so a snapshot's content verifies the same way as an object and as text. Only `CONTENT_FIELDS` are content, and `snapshot_id` is the name `verified` compares them with: any other field is named by no ID, is still neither digested nor checked for its values, and `verified` returns it as it came (a test pins this), so read evidence from `CONTENT_FIELDS` or `SnapshotView.content`. No ID of a finite snapshot changes, and `SNAPSHOT_DIGEST_VERSION` stays 1. `vectors/snapshot/vectors.json` gains `refused-nan`, `refused-infinity` and `refused-negative-infinity`, each carrying the ID the old codec accepted for it. MiDojo's own encoder for a snapshot holding a non-finite float is unchanged. The module docstring now says that an object built to misbehave (a metaclass whose `__name__` raises) raises its own error from a refusal message, and is never returned as verified.
- **The link codec's decoders refuse hostile input as `LinkFault`.** `decode_answer` raised `TypeError` for an answer whose `rejected` was not an object, and `decode_frame`, `decode_answer` and `decode_message` let `RecursionError` escape for deeply nested JSON. `Link` reads answers on a task that catches only `LinkFault`, so either escape ended the reader and left every in-flight request waiting. Each now raises `LinkFault` ("a rejection is an object, not ..." for the first). The wire contract is unchanged, and `vectors/binding/codec.json` pins both refusals.
- **The binding stream starts at frame 0.** `LinkDispatcher` expected the first frame's id to be 0 but checked only the frames after it, so a stream that started at id 1 read as conforming: the expected id now starts at -1, and a first frame with any other id faults the link as a gap or a duplicate.
- **The WebSocket subprotocol is `midojo-binding.v1`.** The service offered and required the messages' API name, `midojo-binding-v1`, as its subprotocol, and the adapter asked for that token: the handshake now offers and requires the subprotocol `midojo-binding.v1` (`midojo_spec.link.SUBPROTOCOL`), and the `bind` frame keeps the API name `midojo-binding-v1` (`API`). A client that offers the old token is refused before the upgrade is accepted.
- **A binding's tool endpoint holds its requests until `bound` is sent.** The service published `/b/<id>/mcp` before it answered the `bind` with `bound`, so a fast target could reach the upstream first. A request now waits for `bound`, and a binding that ends before it gets 401 instead of a route; a target that already read `bound` keeps its access.
- **The driver's dispatcher sends the heartbeat.** `Binding` pinged from a task of its own, so a stalled frame loop still looked alive and the binding never expired. The dispatcher sends `ping` while it waits for frames, and the adapter pings only when a caller asks for an interval (`Binding.open(heartbeat_interval=...)`): a stalled dispatcher now lets the service's expiry end the binding with 1011.
- **An unacknowledged release after the seal reports the lost link.** `close()`, `shutdown()` and leaving the context stored nothing when the service never acknowledged `unbind`, so a sealed evaluation reported an empty `injection_outcomes` as a clean run. They now raise `LinkLostError` (`link-lost`) once the release is complete, keep the sealed snapshot unchanged, and `EvaluationHandle.close_error` reports the error afterwards.
- **A call in flight when the driver hangs up fails at once.** The service failed a lost binding's pending requests and unmounted its app in the same step, which also took down the request that was to carry that failure to the agent: a call waiting on its `start_call` when the driver's socket closed stayed open until the agent's own timeout. The face now counts the calls it is answering, and a loss waits up to `LOSS_DRAIN_SECONDS` (2 seconds) for them to deliver their failure before it unmounts. The upstream is never asked, and the wire contract is unchanged.

## Breaking changes

- **The interceptor moved to `midojo-mim`, with no re-export.** `midojo.interception_service` is `midojo_mim.service`, and the `midojo-intercept-serve` script is the package's (`midojo` installs it, and no longer declares it). `midojo_sdk.placement` is `midojo_mim.placement`. The MCP face of `midojo_sdk.mcp` (`MidojoMCP`, `UpstreamClient`, `BLOCKED_REASON`) is `midojo_mim.mcp`: it takes `recorder=`, `world=` and `sessions=` and no `control_plane_url`, `http` or session token; `midojo_sdk.mcp.MidojoMCP` stays for agent mode and takes `control_plane_url` as before. `midojo_sdk.link`, with `Link`, `LinkRecorder` and `LinkWorld`, is `midojo_mim.link`, and `midojo_sdk` no longer exports those three from its root. `midojo_sdk.context` is `midojo_spec.context` (`midojo_sdk.mcp` and `midojo_sdk.langchain` still export `ToolContext`). `midojo.tool_endpoint.TOOL_PATH`, `bare_host` and `tool_url` are `midojo_mim.endpoint`; `midojo.interception_host`'s listener helpers (`_Server`, `_listen`, `_respond`, `_WILDCARD_HOSTS`, `_SHUTDOWN_SECONDS`) are `midojo_mim.listener`'s `Server`, `listen`, `respond`, `WILDCARD_HOSTS` and `SHUTDOWN_SECONDS`; and `URL_ENV` and `CREDENTIAL_ENV` are `midojo_spec.link`. The `mcp` extra of `midojo-sdk` installs `midojo-mim` and `websockets` instead of FastMCP, and the FastMCP pin moves to `packages/midojo-mim/pyproject.toml`. The face's logger is named `midojo_mim.mcp`, where it was `midojo_sdk.mcp`. Wire IDs and the binding's frames do not change. `LinkRecorder` and `LinkWorld` are the service's end of a binding's stream; the driver's end is the `LinkDispatcher`.
- **`ToolPolicy` and `tool_policy` moved to `midojo_spec.policy`, with no re-export.** The tool policy is the document form a driver states and the interceptor decodes, so both read one implementation on the standard library alone, with the cases in `packages/midojo-spec/vectors/policy/policy.json`. `midojo.injection_spec` no longer defines them or `WRITE_DISPOSITIONS`; import `midojo_spec.policy`. The binding's liveness values and path, `ANSWER_DEADLINE_SECONDS`, `HEARTBEAT_EXPIRY_SECONDS` and `BIND_PATH`, are `midojo_spec.link` beside `HEARTBEAT_INTERVAL_SECONDS`, and `midojo_sdk.binding` no longer defines the first two.
- **The shared contracts moved from `midojo_sdk` to `midojo_spec`, with no re-export.** `midojo_sdk.injection`, `midojo_sdk.injection_spec_schema`, `midojo_sdk.snapshot` and `midojo_sdk.recorder` are now `midojo_spec.injection`, `midojo_spec.injection_spec_schema`, `midojo_spec.snapshot` and `midojo_spec.recorder`; the schema file, `midojo_sdk/schemas/midojo-injection-spec-v1.schema.json`, is `midojo_spec/schemas/midojo-injection-spec-v1.schema.json`; and the frame and message codec of `midojo_sdk.link` (`API`, `SUBPROTOCOL`, `HEARTBEAT_INTERVAL_SECONDS`, `LinkError`, `LinkFault`, `LinkLost`, `Frame`, `Answer`, `Rejection`, `Message`, `encode_frame`, `decode_frame`, `encode_message`, `decode_message`, `rejection_error`, `BIND_FIELDS`, `BOUND_FIELDS`, `UNBOUND_FIELDS`, `INVALID_REQUEST`, `LINK_LOST_REASON`, `MESSAGE_OPS`, `OPS`, `Duplex`, `decode_answer` and `encode_answer`) is `midojo_spec.link`, and `midojo_mim.link`, which took the rest of `midojo_sdk.link`, no longer has any of those names as an attribute. `midojo_sdk` still exports the codec names its root exported (`Frame`, `LinkError` and the others), so code that imports them from the package root is unchanged; code that imported a submodule must follow the move. `midojo_sdk.mcp.MIDOJO_MCP_CAPABILITY`, the MCP interceptor's declared placements, is `midojo_spec.injection.MIDOJO_MCP_CAPABILITY`, beside the `InterceptorCapability` it instantiates, and neither `midojo_sdk.mcp` nor `midojo_mim.mcp` has it as an attribute. The deprecated `ControlPlaneRecorder` stays with the HTTP client, in `midojo_sdk.client`. The plan codec's five `type` aliases are `TypeAlias` assignments, because Python 3.11 cannot parse `type` statements; the names and values are unchanged. `midojo-sdk` depends on `midojo-spec`. Wire IDs (`midojo-binding-v1`, `midojo-injection-spec-v1`) do not change; the recorder's logger is now named `midojo_spec.recorder`.
- **The rubric judge moved to `midojo_spec.rubric_judge`.** `midojo_sdk.rubric_judge` is gone, with no re-export: import `midojo_spec.rubric_judge`. The judge's fixtures moved with it, from `tests/fixtures/rubric/` to `packages/midojo-spec/vectors/rubric/`. `midojo` depends on `midojo-spec`, and `midojo.verifiers.judge` reads `SCHEMA`, `request_id` and `response_problem` from `midojo_spec.judge`, and no longer has them as attributes: import them from `midojo_spec.judge`.
- **The deprecated `Episode*` names are removed.** Importing `midojo.episode`, `midojo.episode_context`, `midojo.episode_document`, `midojo.episode_handle` or `midojo_sdk.episode_schema`, or naming `Episode`, `EpisodeContext`, `EpisodeHandle`, `EpisodeResult`, `EpisodeStep`, `EpisodeRun`, `open_episode` or `EPISODE_DOCUMENT_V1`, fails. Move to the injection-spec names above. The renamed live-cap pieces are breaking too: a script that catches `LiveEpisodeLimitError` or compares `reason` to `live-episode-limit` must use `LiveEvaluationLimitError` and `live-evaluation-limit`, and `MIDOJO_MAX_LIVE_EPISODES` warns as deprecated.
- **Injection-spec documents are `midojo-injection-spec-v1`.** New dumps carry `schema_version: midojo-injection-spec-v1` at the top level, no `episode` wrapper, and name the schema `midojo-injection-spec-v1.schema.json`. Readers accept only that version: the document's old ID and the v0 consumer wrapper are refused, and so is a document with no `schema_version`. A reader that compares document bytes or refuses an unknown `schema_version` must accept the new ID, and a document MiDojo writes no longer validates against the old schema.
- **A verdict names its version.** The document carries `schema_version: midojo-verdict-v1`; code that compares a verdict document byte for byte, or rejects unknown keys, must accept the key. A verdict without it is refused.
- **The synchronous handle owns the run it starts.** `evaluation_handle.open` starts the injection spec's run, starts the sandbox reaper for it, and ends the run on close; a driver script that used to start the run itself must pass the runtime that run owns. An asynchronous `open_evaluation` driver starts no reaper, so a driver killed with `SIGKILL` can leave its OpenShell workspace and sandbox behind: the handle is the leak-safe path.
- **The snapshot encoding is `midojo_spec.snapshot`.** `midojo.control_plane.state.snapshot_digest` still works as a wrapper, but code that imported the encoding's helpers from `midojo` must import them from `midojo_spec.snapshot`. Snapshots computed with `SNAPSHOT_DIGEST_VERSION` 1 keep their IDs.
- **`midojo` depends on `midojo-sdk[mcp]`.** Installing `midojo` now installs the SDK and FastMCP. An environment that pinned the SDK's source to a checkout without the published package, or that installed `midojo` without its dependencies, must install both. FastMCP is pinned as `fastmcp>=3.2.4,<3.3` in `packages/midojo-mim/pyproject.toml`, which the SDK's `mcp` extra and `midojo` install: FastMCP 4.0 removed `fastmcp.tools.tool`, which the face imports `ToolResult` from, and the face wraps FastMCP's private low-level server, so a new minor is a deliberate upgrade.
