# Changelog

What this fork changes in MiDojo's public API. Read [breaking changes](#breaking-changes) before you upgrade. `midojo` and `midojo-sdk` are released together at the same `0.x` version.

## Unreleased

### Added

- **Injection-spec document v1.** `InjectionSpec.to_document`, `InjectionSpec.from_document`, `InjectionSpec.load_document`, `InjectionSpec.dump_document` and `midojo.injection_spec_document` read and write `schema_version: midojo-injection-spec-v1`, a closed document: every member is written, so two dumps of one injection spec are the same bytes. A document under the version's old ID, `midojo-episode-v1`, reads as the same closed shape, with a `DeprecationWarning`, and so does the v0 consumer wrapper (`{"episode": ...}`), with one too; the writer emits neither. The JSON Schema ships in `midojo_sdk.schemas/midojo-injection-spec-v1.schema.json` and `midojo_sdk.injection_spec_schema.load_schema()` loads it. The schema under the old ID stays packaged, for a reader built before the rename.
- **Verdict document version.** A verdict names its format, `midojo-verdict-v1`, so a reader can tell an older record from a newer one. A verdict without the key reads as v0.
- **Plan codec version.** `midojo_sdk.injection.PLAN_CODEC_VERSION` (`midojo-plan-v1`) names the codec `InjectionPlan.to_data` writes, which the v1 injection-spec document's `plan` member holds. The plan carries no version of its own: the document that encloses it names the codec through its `schema_version`, so a change to the bytes the codec writes needs a new document version.
- **Synchronous handle.** `midojo.evaluation_handle.open` returns an `EvaluationHandle` that drives one evaluation from a script with no event loop: `send_turn`, `record_reply`, `seal`, `grade` and `close`. It runs the same `EvaluationContext` on a loop thread of its own, and it states what stays stable (`HANDLE_METHODS`, `HANDLE_API_VERSION`, the exception classes and their `reason` strings). See [the driver guide](docs/guide-driving-midojo.md).
- **Live-episode cap.** A process keeps at most `DEFAULT_MAX_LIVE_EPISODES` (8) handles open; `MIDOJO_MAX_LIVE_EPISODES` overrides the cap and `max_live` lowers it for one call. Opening past the cap raises `LiveEpisodeLimitError` before any port is bound.
- **Runtime capability query.** `midojo.runtimes.runtime_capabilities` answers what a runtime can do from its definition alone: no runtime built, no sandbox created, no provider imported.
- **Placement engine protocol.** `midojo_sdk.placement.PlacementEngine` decides what a plan places in a tool call's result, apart from the wire: the interceptor forwards and records a call, and the engine answers each placement. `PlanPlacementEngine` is the plan's own engine.
- **`midojo.injection_spec.tool_policy`.** The helper reads a spec's `ToolPolicy` as the interceptor's allowlist and block list, so a caller that builds its own host interception applies the spec's policy the same way the handle does.
- **Judge replay.** A grade keeps the judgements it made, and `grade(spec, snapshot, judgements=first.grade.judgements)` replays them with no judge service. A request without a record is unknown, never False. See [Replay](docs/judge-service.md#replay).
- **`midojo-sdk` as a base dependency.** `midojo` now depends on `midojo-sdk[mcp]` instead of reaching into the SDK's checkout: the injection-spec document, the snapshot encoding, the plan codec and the host interceptor's MCP client all live in the published SDK, and `[tool.uv.sources]` keeps the workspace link for development. The `suites`, `pyrit` and `dev` extras are unchanged; `jsonschema>=4.23` joins `dev`, since the tests import it directly.
- **Remote interception.** A driver can run the interceptor in a service of its own. `midojo_sdk.link` carries the `midojo-binding-v1` frames, the messages' API name, over the WebSocket subprotocol `midojo-binding.v1`: `Link` and `Message` on the service's side, `LinkRecorder` and `LinkWorld` on the driver's, and `LinkLost` for a link that ends without an acknowledged `unbind`. `midojo_sdk.binding.Binding` is the driver's adapter: it dials the service's `GET /v1/bindings` upgrade and offers the subprotocol, sends no heartbeat of its own by default (the driver's frame dispatcher sends `ping` every 5 seconds, `HEARTBEAT_INTERVAL_SECONDS`, while it waits for frames), keeps the service's 15-second expiry and 10-second answer deadline (`HEARTBEAT_EXPIRY_SECONDS`, `ANSWER_DEADLINE_SECONDS`), and redacts the bind credential from websockets' DEBUG log. `midojo-intercept-serve` (`midojo.interception_service`) serves each binding's `/b/<id>/mcp` endpoint and holds the upstream, and `evaluation_handle.open` selects it with `interception=RemoteInterception(url, credential)` or, when no option is given, the `MIDOJO_INTERCEPTOR_URL` and `MIDOJO_INTERCEPTOR_CREDENTIAL` pair; neither keeps the interceptor in the driver's process. The SDK's `mcp` extra declares `websockets>=16,<18`, which the adapter imports directly.

### Changed

- **The episode API is the injection-spec API.** The names are `InjectionSpec`, `EvaluationContext`, `EvaluationHandle`, `EvaluationResult`, `EvaluationStep`, `EvaluationRun`, `InjectionSpecDocumentError` and `open_evaluation`; the modules are `midojo.injection_spec`, `midojo.injection_spec_document`, `midojo.evaluation_context` and `midojo.evaluation_handle`, and the SDK's schema module is `midojo_sdk.injection_spec_schema`. The old names stay as deprecated aliases that resolve to the new objects: the modules `midojo.episode`, `midojo.episode_document`, `midojo.episode_context`, `midojo.episode_handle` and `midojo_sdk.episode_schema`; the classes `Episode`, `EpisodeContext`, `EpisodeHandle`, `EpisodeResult`, `EpisodeStep` and `EpisodeRun`; the functions `open_episode` and `ControlPlane.open_episode`; and the constant `EPISODE_DOCUMENT_V1`, which equals `INJECTION_SPEC_DOCUMENT_V1`. The aliases are removed at the next major release.
- **The snapshot encoding moved to `midojo_sdk.snapshot`.** The digest, its canonical encoding and `SNAPSHOT_DIGEST_VERSION` live in the SDK, so a client verifies a snapshot without importing `midojo`. `midojo.control_plane.state.snapshot_digest` remains as a wrapper over it.
- **The served OpenAPI text states the unfinished-call rule.** `_INTERCEPTION_DESCRIPTION` now says that an unfinished call the session can no longer report — revoked or expired — marks `function_calls` evidence incomplete: the sealed record holds a call whose result is unknown.
- **A refused tool call logs one line, not a traceback.** A blocked or denied call still reaches the agent as the same `ToolError`; the driver now gets an INFO line from the SDK and no FastMCP traceback on stderr.
- **`evaluation_handle.open` refuses `run_id` without an open run.** Passing `run_id` with a runtime whose run is not open raises `ValueError` naming `run_id`, before any live slot, port or sandbox. Start the run and pass the runtime it owns, or leave `run_id` out.
- **`open_evaluation` refuses an unenforced tool policy.** The asynchronous API has no interceptor of its own, so it never applied `spec.tools`. It now refuses an injection spec whose policy blocks a tool, unless the `interception` you pass blocks the same tools, rather than opening with the block silently unenforced. The handle's interceptor remains the only place a policy is enforced.

### Fixed

- **The binding stream starts at frame 0.** `LinkDispatcher` expected the first frame's id to be 0 but checked only the frames after it, so a stream that started at id 1 read as conforming: the expected id now starts at -1, and a first frame with any other id faults the link as a gap or a duplicate.
- **The WebSocket subprotocol is `midojo-binding.v1`.** The service offered and required the messages' API name, `midojo-binding-v1`, as its subprotocol, and the adapter asked for that token: the handshake now offers and requires the subprotocol `midojo-binding.v1` (`midojo_sdk.link.SUBPROTOCOL`), and the `bind` frame keeps the API name `midojo-binding-v1` (`API`). A client that offers the old token is refused before the upgrade is accepted.
- **A binding's tool endpoint holds its requests until `bound` is sent.** The service published `/b/<id>/mcp` before it answered the `bind` with `bound`, so a fast target could reach the upstream first. A request now waits for `bound`, and a binding that ends before it gets 401 instead of a route; a target that already read `bound` keeps its access.
- **The driver's dispatcher sends the heartbeat.** `Binding` pinged from a task of its own, so a stalled frame loop still looked alive and the binding never expired. The dispatcher sends `ping` while it waits for frames, and the adapter pings only when a caller asks for an interval (`Binding.open(heartbeat_interval=...)`): a stalled dispatcher now lets the service's expiry end the binding with 1011.
- **An unacknowledged release after the seal reports the lost link.** `close()`, `shutdown()` and leaving the context stored nothing when the service never acknowledged `unbind`, so a sealed evaluation reported an empty `injection_outcomes` as a clean run. They now raise `LinkLostError` (`link-lost`) once the release is complete, keep the sealed snapshot unchanged, and `EvaluationHandle.close_error` reports the error afterwards.

## Breaking changes

- **Injection-spec documents are `midojo-injection-spec-v1`.** New dumps carry `schema_version: midojo-injection-spec-v1` at the top level, no `episode` wrapper, and name the schema `midojo-injection-spec-v1.schema.json`. Readers still accept the document's old ID, `midojo-episode-v1` (the same closed shape), and the v0 consumer wrapper, with or without its `midojo-episode-v2` key, each with a `DeprecationWarning`; the writer emits neither. A reader that compares document bytes or refuses an unknown `schema_version` must accept the new ID, and a document MiDojo writes no longer validates against the old schema.
- **A verdict names its version.** The document carries `schema_version: midojo-verdict-v1`; code that compares a verdict document byte for byte, or rejects unknown keys, must accept the key. A verdict without it still reads as v0.
- **The synchronous handle owns the run it starts.** `evaluation_handle.open` starts the injection spec's run, starts the sandbox reaper for it, and ends the run on close; a driver script that used to start the run itself must pass the runtime that run owns. An asynchronous `open_evaluation` driver starts no reaper, so a driver killed with `SIGKILL` can leave its OpenShell workspace and sandbox behind: the handle is the leak-safe path.
- **The snapshot encoding moved to `midojo_sdk.snapshot`.** `midojo.control_plane.state.snapshot_digest` still works as a wrapper, but code that imported the encoding's helpers from `midojo` must import them from `midojo_sdk.snapshot`. Snapshots computed with `SNAPSHOT_DIGEST_VERSION` 1 keep their IDs.
- **`midojo` depends on `midojo-sdk[mcp]`.** Installing `midojo` now installs the SDK and FastMCP. An environment that pinned the SDK's source to a checkout without the published package, or that installed `midojo` without its dependencies, must install both. The `mcp` extra pins FastMCP as `fastmcp>=3.2.4,<3.3` in `interception/python-sdk/pyproject.toml`: FastMCP 4.0 removed `fastmcp.tools.tool`, which the SDK imports `ToolResult` from, and the SDK wraps FastMCP's private low-level server, so a new minor is a deliberate upgrade.
