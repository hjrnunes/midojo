# Changelog

What this fork changes in MiDojo's public API. Read [breaking changes](#breaking-changes) before you upgrade. `midojo`, `midojo-sdk` and `midojo-spec` are released together at the same `0.x` version.

## Unreleased

### Added

- **Injection-spec document v1.** `InjectionSpec.to_document`, `InjectionSpec.from_document`, `InjectionSpec.load_document`, `InjectionSpec.dump_document` and `midojo.injection_spec_document` read and write `schema_version: midojo-injection-spec-v1`, a closed document: every member is written, so two dumps of one injection spec are the same bytes. The reader accepts that version only. The JSON Schema ships in `midojo_spec.schemas/midojo-injection-spec-v1.schema.json` and `midojo_spec.injection_spec_schema.load_schema()` loads it.
- **Verdict document version.** A verdict names its format, `midojo-verdict-v1`. `Verdict.from_document` reads that version only and refuses a document without `schema_version`.
- **Plan codec version.** `midojo_spec.injection.PLAN_CODEC_VERSION` (`midojo-plan-v1`) names the codec `InjectionPlan.to_data` writes, which the v1 injection-spec document's `plan` member holds. The plan carries no version of its own: the document that encloses it names the codec through its `schema_version`, so a change to the bytes the codec writes needs a new document version.
- **Synchronous handle.** `midojo.evaluation_handle.open` returns an `EvaluationHandle` that drives one evaluation from a script with no event loop: `send_turn`, `record_reply`, `seal`, `grade` and `close`. It runs the same `EvaluationContext` on a loop thread of its own, and it states what stays stable (`HANDLE_METHODS`, `HANDLE_API_VERSION`, the exception classes and their `reason` strings). See [the driver guide](docs/guide-driving-midojo.md).
- **Live-evaluation cap.** A process keeps at most `DEFAULT_MAX_LIVE_EVALUATIONS` (8) handles open; `MIDOJO_MAX_LIVE_EVALUATIONS` overrides the cap and `max_live` lowers it for one call. Opening past the cap raises `LiveEvaluationLimitError` before any port is bound.
- **Runtime capability query.** `midojo.runtimes.runtime_capabilities` answers what a runtime can do from its definition alone: no runtime built, no sandbox created, no provider imported.
- **Placement engine protocol.** `midojo_sdk.placement.PlacementEngine` decides what a plan places in a tool call's result, apart from the wire: the interceptor forwards and records a call, and the engine answers each placement. `PlanPlacementEngine` is the plan's own engine.
- **`midojo_spec.policy.tool_policy`.** The helper reads a spec's `ToolPolicy` as the interceptor's allowlist and block list, so a caller that builds its own host interception applies the spec's policy the same way the handle does.
- **Judge replay.** A grade keeps the judgements it made, and `grade(spec, snapshot, judgements=first.grade.judgements)` replays them with no judge service. A request without a record is unknown, never False. See [Replay](docs/judge-service.md#replay).
- **`midojo-sdk` as a base dependency.** `midojo` now depends on `midojo-sdk[mcp]` instead of reaching into the SDK's checkout: the host interceptor's MCP client lives in the published SDK (the injection-spec schema, the snapshot encoding, the plan codec and the binding frame codec live in `midojo-spec`, which the SDK depends on), and `[tool.uv.sources]` keeps the workspace link for development. The `suites`, `pyrit` and `dev` extras are unchanged; `jsonschema>=4.23` joins `dev`, since the tests import it directly.
- **Remote interception.** A driver can run the interceptor in a service of its own. `midojo_spec.link` is the codec of the `midojo-binding-v1` frames, the messages' API name, over the WebSocket subprotocol `midojo-binding.v1` (`encode_frame`, `decode_frame`, `encode_message`, `decode_message`, `LinkLost` for a link that ends without an acknowledged `unbind`), and `midojo_sdk.link` holds `Link`, `LinkRecorder` and `LinkWorld`, the service's end of the stream. `midojo_sdk.binding.Binding` is the driver's adapter: it dials the service's `GET /v1/bindings` upgrade and offers the subprotocol, sends no heartbeat of its own by default (the driver's frame dispatcher sends `ping` every 5 seconds, `HEARTBEAT_INTERVAL_SECONDS`, while it waits for frames), keeps the service's 15-second expiry and 10-second answer deadline (`HEARTBEAT_EXPIRY_SECONDS`, `ANSWER_DEADLINE_SECONDS`), and redacts the bind credential from websockets' DEBUG log. `midojo-intercept-serve` (`midojo.interception_service`) serves each binding's `/b/<id>/mcp` endpoint and holds the upstream, and `evaluation_handle.open` selects it with `interception=RemoteInterception(url, credential)` or, when no option is given, the `MIDOJO_INTERCEPTOR_URL` and `MIDOJO_INTERCEPTOR_CREDENTIAL` pair; neither keeps the interceptor in the driver's process. The SDK's `mcp` extra declares `websockets>=16,<18`, which the adapter imports directly.
- **`midojo-spec`.** The contracts every reader shares are a package of their own, `midojo-spec` (import `midojo_spec`, `packages/midojo-spec`): the standard library only, no dependency, Python 3.11 and later, so a Garak or consumer environment installs it without MiDojo's runtime. It holds `midojo_spec.injection` (the plan and its codec), `midojo_spec.injection_spec_schema` (the document's schema, as package data), `midojo_spec.snapshot` (the snapshot digest), `midojo_spec.recorder` (the `Recorder` and `WorldState` seams), `midojo_spec.link` (the binding frame codec), `midojo_spec.judge` (the `midojo.judge.v1` request and response rules: `request_id`, `request_problem`, `response_problem`), `midojo_spec.judge_exchange` and `midojo_spec.rubric_judge`, with conformance vectors under `packages/midojo-spec/vectors/` for each contract. A test fails the build if a module imports anything outside the standard library or uses syntax Python 3.11 cannot parse.
- **The judge exchange record.** `midojo_spec.judge_exchange` fixes `midojo.judge-exchange.v1`, one JSONL row for each model request a judge service makes: the key (`request_id`, `ask`), the judge's identity (`model`, `prompt_version`), the messages sent, the reply or the failed call's label, the status, usage and timing (`started_at` is UTC: a row whose time has any other offset is refused), and the SHA-256 of the judge request and of the reply, which equal the digests the sealed grade's judgements hold. `ExchangeLog` appends rows thread-safely (every log on one file in a process shares one lock and count, whatever path each names, and a write that fails is cut back; one process appends to a file at a time), every integer in a row fits 64 bits, `read_exchanges` reads them strictly and refuses an unredacted row whose digests are not those of its text, and `Exchange.observed` redacts secrets from the text in one pass while it keeps the digests of the original; it never rewrites `model` or `prompt_version`, which a replay checks, and refuses a secret that occurs in either. `rubric_judge.http_judge` takes an `observer` that receives each request's outcome, so a judge service keeps a row for a failed call too (a failure the module does not name is observed under its class name and raised as it was), and `JudgeCallError` carries the HTTP `status`.

### Changed

- **The episode API is the injection-spec API.** The names are `InjectionSpec`, `EvaluationContext`, `EvaluationHandle`, `EvaluationResult`, `EvaluationStep`, `EvaluationRun`, `InjectionSpecDocumentError` and `open_evaluation`; the modules are `midojo.injection_spec`, `midojo.injection_spec_document`, `midojo.evaluation_context` and `midojo.evaluation_handle`, and the schema module is `midojo_spec.injection_spec_schema`. The deprecated aliases are gone: the modules `midojo.episode`, `midojo.episode_document`, `midojo.episode_context`, `midojo.episode_handle` and `midojo_sdk.episode_schema`; the classes `Episode`, `EpisodeContext`, `EpisodeHandle`, `EpisodeResult`, `EpisodeStep` and `EpisodeRun`; the functions `open_episode` and `ControlPlane.open_episode`; and the constant `EPISODE_DOCUMENT_V1`. Two host-facing keyword arguments keep their pre-rename names as deprecated forwarding aliases for one cycle: `open_evaluation(episode=...)` and `MidojoInjectionSpecTarget(episode_for_payload=...)` warn `DeprecationWarning` and pass the value to `injection_spec=` and `injection_spec_for_payload=`; passing both names, or neither, raises `TypeError`. The readers of recorded data keep the `episode_trace` and `ipi_episode` notes in a snapshot.
- **The other `episode` spellings follow the glossary.** `YAMLTaskSuite.episode` is `YAMLTaskSuite.injection_spec`, `DEFAULT_EPISODE_NAME` is `DEFAULT_EVALUATION_NAME` (whose value is `evaluation`), a run with no `run_id` is named `evaluation-<hex12>`, the handle's loop thread is `midojo-evaluation-handle`, and the PyRIT target is `MidojoInjectionSpecTarget` with an `injection_spec_for_payload` argument. The live cap is `DEFAULT_MAX_LIVE_EVALUATIONS`, its variable is `MIDOJO_MAX_LIVE_EVALUATIONS`, and the error is `LiveEvaluationLimitError` with reason `live-evaluation-limit`; the old variable `MIDOJO_MAX_LIVE_EPISODES` still sets the cap, with a `DeprecationWarning`. The handle's guide moved to [docs/evaluation-handle.md](docs/evaluation-handle.md), and its example is [examples/drive_evaluation.py](examples/drive_evaluation.py).
- **The snapshot encoding is `midojo_spec.snapshot`.** The digest, its canonical encoding and `SNAPSHOT_DIGEST_VERSION` live in `midojo-spec`, so a client verifies a snapshot without importing `midojo` or the SDK. `midojo.control_plane.state.snapshot_digest` remains as a wrapper over it.
- **The served OpenAPI text states the unfinished-call rule.** `_INTERCEPTION_DESCRIPTION` now says that an unfinished call the session can no longer report — revoked or expired — marks `function_calls` evidence incomplete: the sealed record holds a call whose result is unknown.
- **A refused tool call logs one line, not a traceback.** A blocked or denied call still reaches the agent as the same `ToolError`; the driver now gets an INFO line from the SDK and no FastMCP traceback on stderr.
- **`evaluation_handle.open` refuses `run_id` without an open run.** Passing `run_id` with a runtime whose run is not open raises `ValueError` naming `run_id`, before any live slot, port or sandbox. Start the run and pass the runtime it owns, or leave `run_id` out.
- **`open_evaluation` refuses an unenforced tool policy.** The asynchronous API has no interceptor of its own, so it never applied `spec.tools`. It now refuses an injection spec whose policy blocks a tool, unless the `interception` you pass blocks the same tools, rather than opening with the block silently unenforced. The handle's interceptor remains the only place a policy is enforced.

### Fixed

- **The link codec's decoders refuse hostile input as `LinkFault`.** `decode_answer` raised `TypeError` for an answer whose `rejected` was not an object, and `decode_frame`, `decode_answer` and `decode_message` let `RecursionError` escape for deeply nested JSON. `Link` reads answers on a task that catches only `LinkFault`, so either escape ended the reader and left every in-flight request waiting. Each now raises `LinkFault` ("a rejection is an object, not ..." for the first). The wire contract is unchanged, and `vectors/binding/codec.json` pins both refusals.
- **The binding stream starts at frame 0.** `LinkDispatcher` expected the first frame's id to be 0 but checked only the frames after it, so a stream that started at id 1 read as conforming: the expected id now starts at -1, and a first frame with any other id faults the link as a gap or a duplicate.
- **The WebSocket subprotocol is `midojo-binding.v1`.** The service offered and required the messages' API name, `midojo-binding-v1`, as its subprotocol, and the adapter asked for that token: the handshake now offers and requires the subprotocol `midojo-binding.v1` (`midojo_spec.link.SUBPROTOCOL`), and the `bind` frame keeps the API name `midojo-binding-v1` (`API`). A client that offers the old token is refused before the upgrade is accepted.
- **A binding's tool endpoint holds its requests until `bound` is sent.** The service published `/b/<id>/mcp` before it answered the `bind` with `bound`, so a fast target could reach the upstream first. A request now waits for `bound`, and a binding that ends before it gets 401 instead of a route; a target that already read `bound` keeps its access.
- **The driver's dispatcher sends the heartbeat.** `Binding` pinged from a task of its own, so a stalled frame loop still looked alive and the binding never expired. The dispatcher sends `ping` while it waits for frames, and the adapter pings only when a caller asks for an interval (`Binding.open(heartbeat_interval=...)`): a stalled dispatcher now lets the service's expiry end the binding with 1011.
- **An unacknowledged release after the seal reports the lost link.** `close()`, `shutdown()` and leaving the context stored nothing when the service never acknowledged `unbind`, so a sealed evaluation reported an empty `injection_outcomes` as a clean run. They now raise `LinkLostError` (`link-lost`) once the release is complete, keep the sealed snapshot unchanged, and `EvaluationHandle.close_error` reports the error afterwards.

## Breaking changes

- **`ToolPolicy` and `tool_policy` moved to `midojo_spec.policy`, with no re-export.** The tool policy is the document form a driver states and the interceptor decodes, so both read one implementation on the standard library alone, with the cases in `packages/midojo-spec/vectors/policy/policy.json`. `midojo.injection_spec` no longer defines them or `WRITE_DISPOSITIONS`; import `midojo_spec.policy`. The binding's liveness values and path, `ANSWER_DEADLINE_SECONDS`, `HEARTBEAT_EXPIRY_SECONDS` and `BIND_PATH`, are `midojo_spec.link` beside `HEARTBEAT_INTERVAL_SECONDS`, and `midojo_sdk.binding` no longer defines the first two.
- **The shared contracts moved from `midojo_sdk` to `midojo_spec`, with no re-export.** `midojo_sdk.injection`, `midojo_sdk.injection_spec_schema`, `midojo_sdk.snapshot` and `midojo_sdk.recorder` are now `midojo_spec.injection`, `midojo_spec.injection_spec_schema`, `midojo_spec.snapshot` and `midojo_spec.recorder`; the schema file, `midojo_sdk/schemas/midojo-injection-spec-v1.schema.json`, is `midojo_spec/schemas/midojo-injection-spec-v1.schema.json`; and `midojo_sdk.link` keeps only `Link`, `LinkRecorder` and `LinkWorld`, while the frame and message codec (`API`, `SUBPROTOCOL`, `HEARTBEAT_INTERVAL_SECONDS`, `LinkError`, `LinkFault`, `LinkLost`, `Frame`, `Answer`, `Rejection`, `Message`, `encode_frame`, `decode_frame`, `encode_message`, `decode_message`, `rejection_error` and the rest of it) is `midojo_spec.link`. `midojo_sdk` still exports the names its root exported (`Link`, `LinkRecorder`, `LinkWorld`, `Frame`, `LinkError` and the others), so code that imports from the package root is unchanged; code that imported a submodule must follow the move. `midojo_sdk.mcp.MIDOJO_MCP_CAPABILITY`, the MCP interceptor's declared placements, is `midojo_spec.injection.MIDOJO_MCP_CAPABILITY`, beside the `InterceptorCapability` it instantiates. The deprecated `ControlPlaneRecorder` stays with the HTTP client, in `midojo_sdk.client`. The plan codec's five `type` aliases are `TypeAlias` assignments, because Python 3.11 cannot parse `type` statements; the names and values are unchanged. `midojo-sdk` depends on `midojo-spec`. Wire IDs (`midojo-binding-v1`, `midojo-injection-spec-v1`) do not change; the recorder's logger is now named `midojo_spec.recorder`.
- **The rubric judge moved to `midojo_spec.rubric_judge`.** `midojo_sdk.rubric_judge` is gone, with no re-export: import `midojo_spec.rubric_judge`. The judge's fixtures moved with it, from `tests/fixtures/rubric/` to `packages/midojo-spec/vectors/rubric/`. `midojo` depends on `midojo-spec`, and `midojo.verifiers.judge` reads `request_id` and `response_problem` from `midojo_spec.judge`.
- **The deprecated `Episode*` names are removed.** Importing `midojo.episode`, `midojo.episode_context`, `midojo.episode_document`, `midojo.episode_handle` or `midojo_sdk.episode_schema`, or naming `Episode`, `EpisodeContext`, `EpisodeHandle`, `EpisodeResult`, `EpisodeStep`, `EpisodeRun`, `open_episode` or `EPISODE_DOCUMENT_V1`, fails. Move to the injection-spec names above. The renamed live-cap pieces are breaking too: a script that catches `LiveEpisodeLimitError` or compares `reason` to `live-episode-limit` must use `LiveEvaluationLimitError` and `live-evaluation-limit`, and `MIDOJO_MAX_LIVE_EPISODES` warns as deprecated.
- **Injection-spec documents are `midojo-injection-spec-v1`.** New dumps carry `schema_version: midojo-injection-spec-v1` at the top level, no `episode` wrapper, and name the schema `midojo-injection-spec-v1.schema.json`. Readers accept only that version: the document's old ID and the v0 consumer wrapper are refused, and so is a document with no `schema_version`. A reader that compares document bytes or refuses an unknown `schema_version` must accept the new ID, and a document MiDojo writes no longer validates against the old schema.
- **A verdict names its version.** The document carries `schema_version: midojo-verdict-v1`; code that compares a verdict document byte for byte, or rejects unknown keys, must accept the key. A verdict without it is refused.
- **The synchronous handle owns the run it starts.** `evaluation_handle.open` starts the injection spec's run, starts the sandbox reaper for it, and ends the run on close; a driver script that used to start the run itself must pass the runtime that run owns. An asynchronous `open_evaluation` driver starts no reaper, so a driver killed with `SIGKILL` can leave its OpenShell workspace and sandbox behind: the handle is the leak-safe path.
- **The snapshot encoding is `midojo_spec.snapshot`.** `midojo.control_plane.state.snapshot_digest` still works as a wrapper, but code that imported the encoding's helpers from `midojo` must import them from `midojo_spec.snapshot`. Snapshots computed with `SNAPSHOT_DIGEST_VERSION` 1 keep their IDs.
- **`midojo` depends on `midojo-sdk[mcp]`.** Installing `midojo` now installs the SDK and FastMCP. An environment that pinned the SDK's source to a checkout without the published package, or that installed `midojo` without its dependencies, must install both. The `mcp` extra pins FastMCP as `fastmcp>=3.2.4,<3.3` in `interception/python-sdk/pyproject.toml`: FastMCP 4.0 removed `fastmcp.tools.tool`, which the SDK imports `ToolResult` from, and the SDK wraps FastMCP's private low-level server, so a new minor is a deliberate upgrade.
